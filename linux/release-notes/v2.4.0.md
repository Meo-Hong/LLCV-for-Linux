## 한국어

Windows LLCV 2.3.0~2.4.0 업데이트 가운데 RIFE Vulkan 프레임 보간과 MP4 녹화 길이 정보를 리눅스판에 반영했습니다.

### RIFE 프레임 보간 (F7)

- **설정 → 영상 → 프레임 보간 (F7)**에서 **RIFE Vulkan 프레임 보간 사용**을 켜면, 24~60fps의 1920 × 1080 SDR 영상에서 캡처한 두 프레임 사이마다 생성 프레임을 보여 줍니다. 30fps 게임 화면이 60fps처럼 부드럽게 움직입니다. 처음에는 꺼져 있습니다.
- Practical-RIFE 4.25 Fast 모델(Windows판 2.4.0 패키지의 파일 그대로)을 ncnn과 Vulkan으로 GPU에서 실행합니다. 화면은 OpenGL로 그리고, 같은 GPU에서 OpenGL과 Vulkan이 텍스처를 공유합니다(`GL_EXT_memory_object_fd`, `GL_EXT_semaphore_fd`).
- 새 프레임이 오면 직전 프레임과의 중간 프레임을 계산해서, 반 프레임 시간 안에 끝나면 생성 프레임을 먼저, 반 프레임 뒤에 새 프레임을 보여 줍니다. 늦으면 새 프레임만 보여 줍니다. 원본 프레임은 보간하지 않을 때보다 약 반 프레임 늦게 표시되며, 게임이 빨라지거나 입력 반응이 좋아지지는 않습니다.
- **HUD 보호**: 기본값 **밝기와 색 윤곽**이 하트, 글자, 점수처럼 고정된 화면 요소가 일그러지지 않게 합니다. **밝기 윤곽**이나 **끄기**도 고를 수 있습니다.
- **보간 중 캡처 프레임레이트**: 보간을 켜 두면 선택한 픽셀 형식 그대로 1920 × 1080으로 캡처합니다. 프레임레이트는 **프레임레이트와 같게**(기본), **자동**(24~60fps 중 가장 높은 값), 장치가 지원하는 값 중에서 고릅니다. 저장한 영상 설정은 바뀌지 않습니다.
- 저지연 화면 표시 방식에서만 동작합니다. P010(HDR), VSync, 오디오 전용 모드에서는 원본 프레임을 표시합니다.
- **F7**(또는 **Alt → 보기 → RIFE 프레임 보간**)로 재생 중에 바로 끄고 켭니다. 이 선택은 다음 실행에도 유지됩니다.
- 화면 표시에만 적용되며, 녹화와 스크린샷은 캡처한 프레임 그대로입니다. Tab 진단에 생성, 기한 초과, 처리 중 건너뜀 횟수와 GPU 시간이 나옵니다.
- RIFE를 시작할 수 없으면(Vulkan 드라이버 없음, 확장 없음 등) 알림으로 이유를 알려 주고 원본 프레임을 표시합니다.

GeForce RTX 2070에서는 한 프레임에 약 10 ms가 걸려서 30fps 입력은 모두 보간되고, 60fps 입력은 기한(8.3 ms)을 넘겨 원본 프레임만 표시됩니다.

### 녹화

- 녹화 중에는 지금처럼 fragmented MP4로 기록하고, 녹화나 분할 파일이 정상적으로 끝나면 파일 끝에 전체 샘플 색인을 덧붙입니다(hybrid MP4). 파일 관리자처럼 MP4 헤더만 읽는 프로그램에서도 녹화 길이가 보입니다. 영상을 다시 인코딩하거나 복사하지 않습니다.
- FFmpeg 7.1 이상이 필요하며 `.deb` 패키지의 내장 FFmpeg 7.1.1이 지원합니다. 시스템 FFmpeg가 더 오래되었거나 녹화가 중간에 끊긴 파일은 fragmented MP4 그대로이고, 이미 있던 녹화 파일은 바꾸지 않습니다.

### 패키지

- amd64 `.deb`, x86_64 `.rpm`, Arch 패키지에 프레임 보간이 들어 있습니다. Raspberry Pi(arm64·armhf) 패키지에는 없습니다.
- ncnn 20261020에 Windows판 패치를 적용해 앱에 정적으로 넣습니다. Vulkan 로더(`libvulkan1`, `vulkan-loader`, `vulkan-icd-loader`)는 실행 중에 열며, `.deb`와 `.rpm`은 권장 패키지로 설치합니다.
- 패키지 크기가 RIFE 모델(약 25 MB)과 ncnn만큼 커졌습니다.

Windows판과 다른 점:

- NVIDIA VFG(DLSS Frame Generation)는 NVIDIA의 Windows 런타임이 필요해서 옮기지 않았습니다. 보간 방식은 RIFE Vulkan 하나입니다.
- 2.3.2의 재생 GPU 선택은 넣지 않았습니다. 리눅스판은 화면을 출력하는 GPU(OpenGL과 같은 GPU)에서 RIFE를 실행합니다.
- 2.3.0의 녹화 표시, 오디오 연결 실패 시 영상만 재생, F1 단축키 목록은 리눅스판에 이미 있습니다.

기존 설치 경로, 설정, 사용자 지정 단축키는 그대로 유지합니다. 프레임 보간에는 F7을 쓰며, 사용자 지정 단축키가 이미 F7을 쓰고 있으면 비어 있는 다른 기능 키를 지정합니다(F1이나 **설정 → 안내 · 로그**에서 확인).

## English

This release brings the RIFE Vulkan frame interpolation and the MP4 recording length of the Windows LLCV 2.3.0 to 2.4.0 updates to Linux.

### RIFE frame interpolation (F7)

- **Settings → Video → Frame interpolation (F7) → Use RIFE Vulkan frame interpolation** shows a generated frame between every two captured frames of 1920 × 1080 SDR video at 24 to 60 fps. 30 fps game footage moves as smoothly as 60 fps. It is off by default.
- The Practical-RIFE 4.25 Fast model (the files of the Windows 2.4.0 package, unchanged) runs on the GPU through ncnn and Vulkan. The display stays on OpenGL, and OpenGL and Vulkan share textures on the same GPU (`GL_EXT_memory_object_fd`, `GL_EXT_semaphore_fd`).
- When a frame arrives, the frame between it and the previous one is computed. If it is ready within half a frame time, the generated frame is shown first and the new frame half a frame later; otherwise only the new frame is shown. Each original frame appears about half a frame later than without interpolation, and the game does not run faster nor does input response improve.
- **HUD protection**: the default **Luma and color edges** keeps fixed screen elements such as hearts, text and score counters from warping. **Luma edges** and **Off** are also available.
- **Capture rate while interpolating**: with interpolation on, the capture runs at 1920 × 1080 with the selected pixel format. The rate is **Same as Frame rate** (default), **Auto** (the highest from 24 to 60 fps) or one the device lists. The saved video settings do not change.
- It needs Immediate presentation. P010 (HDR), VSync and the audio-only mode show the original frames.
- **F7** (or **Alt → View → RIFE frame interpolation**) turns it off and on during playback. The choice is kept for the next start.
- It is display only; recordings and screenshots keep the captured frames. The Tab diagnostics show the generated, late and busy counts and the GPU time.
- When RIFE cannot start (no Vulkan driver, missing extensions and so on), a notice gives the reason and the original frames are shown.

On a GeForce RTX 2070 a frame takes about 10 ms, so 30 fps input is fully interpolated, while 60 fps input misses its 8.3 ms deadline and shows the original frames only.

### Recording

- Recordings are still written as fragmented MP4, and when a recording or a split part ends normally, a complete sample index is added at the end (hybrid MP4). Programs that read only the MP4 header, such as file managers, now show the length. Nothing is re-encoded or copied.
- This needs FFmpeg 7.1 or newer; the built-in FFmpeg 7.1.1 of the `.deb` packages has it. With an older system FFmpeg, and for interrupted recordings, files stay fragmented MP4. Existing recordings are not changed.

### Packages

- The amd64 `.deb`, the x86_64 `.rpm` and the Arch package include frame interpolation. The Raspberry Pi (arm64, armhf) packages do not.
- ncnn 20261020 with the Windows LLCV patch is linked statically. The Vulkan loader (`libvulkan1`, `vulkan-loader`, `vulkan-icd-loader`) is opened at run time and is recommended by the `.deb` and `.rpm`.
- The packages are larger by the RIFE model (about 25 MB) and ncnn.

Differences from the Windows build:

- NVIDIA VFG (DLSS Frame Generation) needs NVIDIA's Windows runtime and is not ported. RIFE Vulkan is the only method.
- The playback GPU choice of 2.3.2 is not included. On Linux, RIFE runs on the GPU that drives the display (the OpenGL GPU).
- The 2.3.0 recording indicator, video-only playback when audio fails to connect, and the F1 shortcut list already exist on Linux.

Installation paths, settings and custom shortcuts are kept. Frame interpolation uses F7; if a custom shortcut already uses F7, a free function key is assigned instead (see F1 or **Settings → Guide & logs**).
