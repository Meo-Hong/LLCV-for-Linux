## 한국어

Windows LLCV 2.1.8 업데이트를 리눅스판에 반영했습니다.

- **UYVY(8비트 4:2:2) 입력**: 재생, 스크린샷, 녹화에 지원합니다. 자동 선택은 그대로 NV12, YUY2를 먼저 고릅니다. 바이트 순서는 셰이더에서 바로 읽어서, CPU 변환이나 복사가 늘지 않습니다.
- **RGB 입력 추가**(리눅스판 전용): 기존 BGR24에 더해 32비트 RGB(BGR32)와 RGB24를 재생, 스크린샷, 녹화에 지원합니다. UVC 장치가 RGB32로 내보내는 영상은 리눅스에서 BGR32(커널에 따라 `XR24` 또는 `BGR4`)로 보입니다. RGB는 YUV보다 대역폭이 커서 USB 3.0에서는 1080p30 이하가 현실적입니다. 장치가 목록에 올린 형식 코드를 그대로 요청하도록 바꿔서, 같은 배치를 다른 이름으로 보고하는 장치도 열립니다.
- **CMAA2 → NIS 업스케일링 안정성**: 아주 조밀한 프레임이 CMAA2 작업 버퍼(후보·혼합 항목·위치 목록)를 넘치면, 일부만 안티에일리어싱한 화면을 보여 주지 않고 그 프레임만 CMAA2를 건너뜁니다. NIS 확대는 계속하고, 다음 정상 프레임부터 CMAA2가 다시 적용됩니다. 잘못되었거나 끝나지 않은 혼합 목록도 적용하지 않습니다.
- **지원하지 않는 픽셀 형식 안내**: LLCV가 쓸 수 없는 형식만 제공하는 장치도 이제 목록에 나타나고, 설정 화면이 그 형식 이름(최대 3개)을 알려 줍니다. 선택한 해상도에 그런 형식만 있을 때도 따로 안내합니다. 자동 장치 선택은 계속 지원하는 형식이 있는 장치를 먼저 고릅니다. 건너뛴 형식과 프레임 크기는 모두 로그에 남습니다.

Windows판과 다른 점:

- 리눅스판은 UYVY도 녹화합니다(FFmpeg가 바로 변환). Windows판은 UYVY 녹화를 막습니다.
- HDYC는 리눅스 V4L2에 별도 형식이 없어서 장치가 UYVY로 보고합니다. 색 공간은 다른 SDR 입력처럼 장치 정보와 **색 공간·SDR 색 범위** 설정을 따릅니다.
- NIS 가장자리 수정은 2.1.7에서 이미 반영했습니다. 이번에는 NIS 뷰포트 범위 검사도 Windows판과 맞췄지만, 리눅스판에서는 뷰포트 경로를 쓰지 않습니다.

기존 설치 경로, 설정, 사용자 지정 단축키는 그대로 유지합니다.

## English

This release brings the Windows LLCV 2.1.8 update to Linux.

- **UYVY (8-bit 4:2:2) input** for playback, screenshots and recording. Auto selection still picks NV12, then YUY2, first. The shader reads the byte order directly, so there is no extra CPU conversion or copy.
- **More RGB input** (Linux only): besides the existing BGR24, 32-bit RGB (BGR32) and RGB24 now work for playback, screenshots and recording. Video that a UVC device sends as RGB32 appears on Linux as BGR32 (`XR24` or `BGR4`, depending on the kernel). RGB needs more bandwidth than YUV, so on USB 3.0 expect 1080p30 or lower. Capture now requests the exact format code the device listed, so devices that report the same layout under another name also open.
- **Safer CMAA2 → NIS upscaling**: if a very dense frame overflows the CMAA2 work buffers (candidate, blend-item or location list), that frame skips CMAA2 instead of showing partial anti-aliasing. NIS keeps scaling, and CMAA2 returns on the next normal frame. Invalid or unfinished blend lists are not applied either.
- **Unsupported pixel format notice**: devices that offer only formats LLCV cannot use now appear in the list, and settings name those formats (up to three). The selected resolution gets its own notice when it has only such formats. Auto device selection still prefers devices with supported formats. Every skipped format is logged with its frame sizes.

Differences from the Windows build:

- Linux also records UYVY (FFmpeg converts it directly). The Windows build blocks UYVY recording.
- HDYC has no separate V4L2 format on Linux, so devices report it as UYVY. Its color follows the device information and the **Color matrix** and **SDR color range** settings, like other SDR input.
- The NIS edge fix was already in 2.1.7. The NIS viewport bounds checks now match the Windows copy too, but the Linux build does not use the viewport path.

Installation paths, settings and custom shortcuts are kept.
