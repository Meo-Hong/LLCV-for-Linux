# 직접 P010 → scRGB 비교 프로토타입 (2026-09-16)

## 범위

`LLCV_HDR_SCRGB_PROTOTYPE=ON` 전용 빌드에만 포함한다. 기본 릴리스 구성은 OFF.
기존 VP/HDR10 경로는 비교 대상으로 유지하며 `--hdr-output hdr10`으로 선택한다.
기본 진단 출력은 scRGB다. F2 재실행에도 출력 선택을 전달한다.

P010 R16/R16G16 평면 뷰에서 Limited YCbCr/BT.2020 NCL을 복원하고 PQ EOTF,
선형 BT.2020→BT.709 변환과 80 nit 정규화를 한 픽셀 셰이더에서 수행한다.
출력은 R16G16B16A16_FLOAT / RGB_FULL_G10_NONE_P709이며 음수·1 초과값을 보존한다.
HDR10 입력 정책, 기존 3개 업로드 표면, Flip/Present 정책과 오디오는 유지한다.
톤매핑, 색상 보정, 별도 영상 중간 표면, CPU 변환, 정상 재생 중 읽기/파일 저장은 추가하지 않는다.

scRGB에서는 VP를 생성·실행하지 않는다. Sharp 대신 선형 보간만 적용하므로
현재 비교는 1:1 또는 Sharp 비활성 상태로 진행해야 한다. UI는 scRGB 선형광에서 합성한다.

## 확인

- 기존 HDR10 테스트(회색 램프, 729색, UI/패딩 등) 유지 통과.
- scRGB 0~10000 nit 기준 패치, 채도가 높은 원색, 음수 및 1 초과 채널 보존.
- 80 nit 기준과 Windows UI white/80 관계, 투명 UI, 검정 반투명 UI.
- Left/Top-left 색차 위치를 실제 공간 변화 P010 입력으로 구분해 검사.
- 실제 presentUploaded 호출에서 scRGB 렌더/OSD/Present 수행, D3D11 디버그 경고·오류 검사.
- FP16 F8 파일 저장, 입력 바이트 일치, 같은 출력 프레임 일치, 요청당 1회 저장.
- HDR10↔scRGB 및 scRGB→SDR 재초기화/자원 해제.
- 관련 6개 테스트 통과. 기본 기능 비활성 구성의 main.cpp 컴파일도 확인.

## 성능 측정 한계

로컬 RTX 3080, 2560×1440, 동일 프레임 20회 준비 후 100회 GPU 영상 처리 반복:
scRGB 약 42~49 μs/프레임. 캡처·업로드·OSD·Present·실제 디스플레이 지연을 포함하지 않는다.
VP 결과는 timestamp가 사실상 0으로 나와 유효하지 않다. 이를 0비용으로 해석하거나
두 경로의 속도 우열/동일 지연을 주장하지 않는다.

FP16 출력은 RGB10보다 픽셀당 바이트가 두 배다. 정상 재생 중 추가 프레임 큐나
매 프레임 자원 할당은 없지만 추가 연산/출력 대역폭 비용은 있다.

사용자 환경에서 실제 과포화 해결 여부와 종단간 지연은 아직 미검증. 공개 릴리스하지 않음.
