# v1.2.8 과포화 제보 재검증 — 2026-09-16

## 후속 상태 요약

아래 최초 검사 뒤 실제 P010/변환 결과 쌍을 확보했다. '아직 수집하지 않았다'는
하단 문장은 당시의 기록이며 현재의 미수집 상태를 뜻하지 않는다.

- GC573 동일 장면 HDR10 쌍 `34CB049F-5376-4359-939D-D8DE2579AF4D`와 scRGB 쌍
  `FC9078D8-770A-442E-95A7-19700D5A3A4A`를 읽기 전용 비교 도구로 다시 계산했다.
  입력 샘플 일치율 99.4068%, 같은 입력의 평탄 영역 2,345,647픽셀이다.
  PQ 10-bit로 환산한 출력 경로 간 차이의 99백분위는 약 0.402 코드이며,
  유색 평탄 영역 16,021픽셀에서는 약 3.664 코드다. 최대 차이는 전체 평탄 마스크에서
  약 22.834 코드이므로 모든 픽셀이 일치한다고 주장하지 않는다.
  scRGB 직접 셰이더는 독립 CPU 식과 비교해 설정한 부동소수점 허용 오차를 넘는
  채널이 0개였고 비유한 값도 없었다.
- 이 비교는 Windows 합성 이전의 출력이며 실제 모니터 휘도/색 정확도나
  입력의 PQ/BT.2020 인코딩 자체를 증명하지 않는다. 두 경로 모두 동일한
  입력 해석을 사용하므로 잘못된 입력 가정까지 배제할 수는 없다.
- 후속 OFF 명령 수락 후에도 과포화가 남았다. 따라서 하드웨어 톤매핑 제어를
  해결책으로 확정하지 않고 일반 빌드에서 제외했다. 상세는
  `HARDWARE_TONE_MAPPING_AUDIT.ko.md`의 현재 상태를 따른다.
- NV12 녹빛은 OBS에서도 관찰됐다는 사용자 확인에 따라 이번 HDR 작업에서 제외한다.
  앱 무관이 입증됐다는 뜻은 아니며 NV12 변환/채도/감마는 수정하지 않는다.
- 색차 배치 6을 7로 자동 변경하는 우회는 추가하지 않는다. 실제 ezcap 튜플의
  거부와 명시적 cosited 튜플 허용, GC573 강제 켬/끔 및 HDR/SDR 메타데이터 전환
  1,000회 반복 검사를 추가했다. 테스트는 실제 캡처 장치를 사용하지 않는다.

## 범위

GC573의 P010/HDR 강제 켬·끔 스크린샷과 로그에 따른 재검증이다.
장치는 메타데이터를 제공하지 않았고, Windows 출력은 마지막 로그에서 HDR 10-bit였다.
스위치 HDR이 켜졌다는 사용자 확인은 있지만 실제 전달된 P010 프레임은 확보하지 않았다.
원본 픽셀, Windows 합성 결과, 실제 화면과 스크린샷 저장 결과를 동일한 데이터로
비교하지 않았으므로 과포화의 실제 원인이나 해결 여부를 확정하지 않는다.

## 코드 및 공식 API 확인

- HDR 입력과 출력에 각각 PQ/BT.2020 색공간을 지정한다. 영상에 별도 PQ 감마를
  반복 적용하거나 UI white를 곱하는 앱 코드 경로는 확인되지 않았다.
- HDR VP 자동 처리는 비활성화한다. 업로드는 P010 16-bit 컨테이너와 전달 stride를
  사용하며 기존 3개 표면을 순환한다.
- 색 정보 없는 P010에서 강제를 끄면 SDR 해석 경로다. HDR에서 SDR로의 톤매핑이
  아니므로 끈 화면의 밝기를 HDR 정상 여부의 기준으로 사용할 수 없다.
- GPU 출력 코드 검증은 DWM/모니터의 최종 표시나 스크린샷 색 관리를 검증하지 않는다.

## 추가 GPU 회귀 검사

실제 앱 렌더러를 호출하되, 알려진 합성 P010 입력을 사용했다.

- 고채도·원색을 포함한 9×9×9 RGB 조합 729개를 BT.2020 NCL Limited P010으로
  양자화한 후 GPU 출력과 독립 CPU 역변환을 비교했다.
  최대 오차 0.558/1023 코드. 광범위한 과포화/조기 클리핑은 재현되지 않았다.
- 0.1, 1, 10, 80, 100, 203, 280, 1000, 4000, 10000nit 회색 입력:
  203nit -> RGB10 594 -> PQ 역해석 202.92nit,
  1000nit -> 770 -> 1007.93nit,
  4000nit -> 924 -> 4024.34nit. 입력/출력 양자화를 포함한다.
  이는 모니터에서 측정한 휘도가 아니다.
- Windows UI white 80/280/1000nit 변경 시 숨겨진 OSD가 영상 코드를 바꾸지 않음을 확인했다.
- padding을 포함한 P010 두 색 영역을 9프레임/3개 업로드 표면으로 반복 검증했다.
  stride 및 UV 시작 위치 오염은 재현되지 않았다.
- 같은 203nit PQ 입력을 실제 강제 끔 P010 SDR 경로에 전달하면 RGB8 147이 된다.
  이 경로가 HDR 톤매핑이 아니라는 대조 검사다.
- GPU debug warning/error 0. 관련 6개 검사 6/6 통과(3.27초).

## 결론 및 변경 범위

이번 합성 검사는 지원하는 수식/API 경로의 회귀 검사이며 실장치 호환성 인증이 아니다.
GC573 실프레임에 적용할 밝기/채도 값을 추측해 변경하지 않았다.
앱 런타임, EXE, 기존 릴리스, 기본 옵션은 변경하지 않았고 검사 코드와 기록만 추가했다.
색차 옵션과 프리릴리스는 보류 상태다.
다음 구분에 필요한 것은 실제 P010 프레임과 같은 프레임의 HDR 변환 결과이며,
스크린샷만으로 실제 입력 PQ/SDR 여부나 Windows 출력 단계의 클리핑을 확정할 수 없다.
